# ScoreDeck CS 2.16.0 · 模块化对阵与赛事启用校验

在 2.15.0 自定义赛段流程基础上升级。完整解压 Windows x64 便携包，运行 `ScoreDeck CS.exe`，左侧版本应为 2.16.0。

## 设置并启用赛事

1. 进入「赛事设置」或「赛段与流程」，添加小组赛、瑞士轮、Playoff 或单场对决。新赛事默认空白，可添加多个赛段并调整顺序。
2. 配置参赛队伍。赛制模板参数也会实时保存为草稿，刷新后可继续编辑；点击「应用模板并重建本赛段」生成比赛。
3. 打开「对阵模块」，逐场设置轮次名称、BO 数、入场来源及对阵类型。淘汰赛模板中的对阵和附加对阵可单独删除；被删除对阵的上游连线变为「待连接」。
4. 普通对阵的胜者、败者必须各有一个明确去向：本赛段的具体比赛、后续赛段的具体比赛 A/B 位，或终结状态。跨赛段入场位置的选项也列出其对应比赛、轮次与 A/B 位。循环赛入场位置会列出该队参与的多场比赛。
5. 决赛对阵自动固定为「胜者 → 冠军、败者 → 亚军」；季军赛自动固定为「胜者 → 季军、败者 → 殿军」。需要继续晋级的对阵应使用「普通对阵」。切回普通对阵后，两条出口都需重新配置。
6. 图上点击普通对阵的胜／负端点或最终排名端点，再点击目标位置即可连线。决赛与季军赛的固定出口不可改线；空的模板入场位置可以直接改接到指定比赛。已有队伍或晋级来源的目标需先清空原来源。
7. 点击「检查全部路径」查看遗漏；点击「校验并启用」通过完整校验后，才能录入赛果和使用赛事播出。设置自动保存，也可点击「保存设置」。未完成的草稿可以保存和刷新恢复。

## 终结状态与校验

终结状态只允许：淘汰、Qualified、冠军、亚军、季军、殿军。普通附加对阵默认「待连接」，不能靠默认淘汰掩盖遗漏。标准淘汰模板自带的败者淘汰路线仍会明确显示，可自行改接季军赛或其他对阵。四队 GSL 的晋级出口需要明确选择 Qualified 或下个赛段。

启用检查会追踪每个出口的所有后续路径，确认最终到达终结状态；同时拒绝未连接出口、空来源、没有比赛的目标位置、循环连线、倒退到此前赛段、重复占位、淘汰对阵重复使用入场位置及未应用的模板草稿。所有校验在服务端再次执行，不能仅修改客户端启用标记绕过。

循环赛与瑞士轮的轮内比赛按赛制推进，最终排名出口参与同样的完整路径检查。轮内比赛可改轮次名称和 BO；修改轮内结构应调整赛制模板，附加对阵可独立编排且不计入循环赛积分。

修改赛段、连线、角色、BO、轮次名称或参赛来源会让赛事返回草稿，需要重新校验并启用。修改日期、时间、播出页码或录入正常赛果不影响启用状态。旧版自定义赛事升级后先作为草稿检查；原有赛果保留。旧的自由文本终结标签如不在上述列表中，会变为待连接；旧「晋级」终结标签迁移为 Qualified。

赛果完成后，系统自动输送下一场队伍并记录队伍终结结果 `flowOutcomes`。上游结果或参赛者变化会清空受影响的下游赛果，保留失效赛果快照供核查。

## 赛制与播出

延续 2.15.0：小组数量、每组人数和赛制独立配置；单／双循环支持 BO1/2/3/5，四队 GSL 每场支持 BO1/3/5；2—32 队任意人数单败；八队双败（总决赛不重置）；16 队瑞士轮（3 胜晋级、3 负淘汰）；任意赛段可加入 BO1/3/5 附加对阵。

赛程图根据实际连线生成。决赛与季军赛独立排列，胜者线和败者线区分显示。OBS 输出和自动轮播继续支持指定赛段与页码；未启用时赛事主输出显示「赛事尚未启用」。独立 RadarHUD、VoiceBridge、中场与回放工具继续沿用既有接口。

## 升级与源码

关闭旧程序后完整解压新包。升级前可在「归档与恢复」导出完整 `.sdpack`。赛事设置、草稿、启用状态、连线及终结赛果随赛事归档保存。不要使用旧版编辑新格式赛事。

引擎：`server/tournament-flow.cjs`，浏览器共享 `dist/assets/tournament-flow.js`。界面：`ui/tournament-flow.js`。`npm run build:ui` 接入现有 React 程序；`npm test` 完整回归；`npm run test:flow` 流程专项。验证记录见 `VERIFICATION-2.16.0.md`。

本版没有进行真实 Windows、CS2/GOTV、OBS 或多人 TeamSpeak 联动测试。
